## Часть 1. Задача и общие правила

Ты — опытный фронтенд-разработчик и методист по криптограмотности: энтузиаст блокчейна и свободной экономики, но неукоснительно соблюдаешь законы. Твоя задача — воссоздать веб-приложение **Cryptocube** в точности по этому ТЗ: структура, модули, дизайн, тексты и поведение должны совпасть. Ничего не упрощай, не меняй тексты и не добавляй своих функций.

### Идея
Когда-то существовал бумажный «Обучающий кубик»: пользователь по шагам сканировал QR-коды на упаковке и гранях деревянного кубика, проходил задания и в конце умел уверенно пользоваться криптовалютой и смарт-контрактами, а кубик оставался у него холодным кошельком. Cryptocube — виртуальный симулятор этой идеи: **6 кубиков × 6 граней = 36 практических заданий**, в каждой грани спрятана ловушка. Все деньги, адреса, seed-фразы и сети ненастоящие, к реальным блокчейнам ничего не подключается.

### Что сдать (ровно 4 файла)
1. `index.html` — одна страница без сборки и без зависимостей (чистые HTML + CSS + JavaScript ES2020, весь код инлайном, около 2 150 строк и 420 КБ). Подключаются только шрифты Google Fonts.
2. `api/ask.js` — серверная функция Vercel для ИИ-помощника (код дан дословно в Части 4).
3. `vercel.json` — ровно `{ "cleanUrls": true }`.
4. `README.md` — описание проекта (структура дана в конце Части 1).

### Правовые рамки (обязательно отразить в интерфейсе и текстах)
- Платформа учебная: не принимает и не хранит криптовалюту, не проводит обмен, не даёт инвестиционных рекомендаций.
- Сценарии с оплатой услуг разыграны в учебной юрисдикции «Кубания». В РФ оплата товаров и услуг криптовалютой запрещена (259-ФЗ).
- Нигде не просить реальные документы, seed-фразы, ключи.
- В шапке всегда видна плашка «Учебная среда» (title: «Все деньги, адреса и seed-фразы здесь ненастоящие»).

## Часть 1.1. Дизайн-система

**Шрифты** (Google Fonts, один `<link>` с `preconnect`): `Unbounded` 500/700 — заголовки и цифры (`--font-display`), `Onest` 400/500/600 — основной текст (`--font-body`), `JetBrains Mono` 400/600 — адреса, хэши, seed-слова (`--font-mono`). Базовый шрифт: 15px/1.5.

**Палитра** — в духе ethereum.org: белый с лёгким фиолетовым оттенком, фиолетовый акцент, светлая и тёмная темы (тёмная по `prefers-color-scheme` и принудительно через `:root[data-theme="dark"]`, светлая через `data-theme="light"`). Все токены и полный CSS даны дословно в Части 4, используй их без изменений.

**Цвета кубиков** (как у детских кубиков, каждому кубику и каждой грани свой цвет): `--c1 #6c24df` (фиолетовый), `--c2 #3c4ceb` (синий), `--c3 #0cb988` (бирюзовый), `--c4 #f6109e` (розовый), `--c5 #fbbf24` (жёлтый), `--c6 #d97706` (янтарный). На `--c6` (и на 6-й грани) текст тёмный `#2b1e00`, на остальных белый. Для текста цветом кубика есть «чернильные» варианты `--i1…--i6`. `body[data-cube="cN"]` переключает `--cube`/`--cube-ink`: им окрашены подчёркивание заголовка h1 (6px), активная кнопка переключателя кубиков, верхняя полоса 5px у карточки задания и надзаголовок (eyebrow).

**Фон**: четыре мягких радиальных свечения цветами c1, c3, c2, c4 по углам (`color-mix` 16% в светлой, 13% в тёмной теме, `background-attachment: fixed`) плюс слой `#bgsyms` — 18 символов криптовалют `₿ Ξ ◎ Ł ɱ ⓩ ₮ Ð ₳ ✕ ₿ Ξ ◎ ₮ ⓩ Ł ɱ Ð`, раскиданных по заданным позициям `[x%, y%, размер px, поворот°]`:
`[4,8,64,-12] [88,6,48,10] [72,30,36,18] [14,38,42,8] [92,52,58,-8] [3,66,50,14] [46,88,44,-16] [84,84,40,6] [30,14,30,20] [58,60,34,-6] [38,46,26,12] [66,6,28,-18] [22,92,38,4] [96,30,26,22] [52,24,22,-10] [8,22,24,16] [76,70,24,-14] [28,74,30,10]`, цвета по кругу c1…c6, прозрачность 0.12, `z-index:-1`, `pointer-events:none`.

**Деревянный 3D-кубик** (карта граней): сцена 210px с `perspective: 700px`, куб 140×140, `transform-style: preserve-3d`, переход `0.9s cubic-bezier(.2,.7,.2,1)` (отключается при `prefers-reduced-motion`). Грани: бук `--wood #dcbf98`, край `--wood-edge`, текстура волокон `repeating-linear-gradient(100deg, …)`, «выжженный лазером» текст `--burn #2b1e14`, номер в кружке и короткое название. Пройденная грань (`.lit`) заливается цветом своей грани c1…c6, номер становится белым квадратом. Поворот куба к текущей грани:
`1: rotateX(-14deg) rotateY(20deg)`, `2: rotateX(-14deg) rotateY(-70deg)`, `3: rotateX(-14deg) rotateY(-160deg)`, `4: rotateX(-14deg) rotateY(110deg)`, `5: rotateX(-80deg) rotateY(20deg)`, `6: rotateX(76deg) rotateY(20deg)`.

## Часть 1.3. Игровая механика и состояние

- **XP**: +50 за каждый шаг, +100 за полностью пройденную грань. Общий XP в шапке — сумма по всем кубикам.
- **Прогресс** в `localStorage`: `cryptocube-1` … `cryptocube-6` (состояние каждого кубика), `cryptocube-cur` (открытый кубик), `cryptocube-lang` (`ru`/`en`), `cryptocube-welcome` (приветствие показано). Все обращения к хранилищу в try/catch. У кубиков 3–6 в состоянии есть версия `v`; при несовпадении состояние создаётся заново.
- **Грани открываются строго по порядку.** Кнопки переключателя кубиков доступны всегда (кубики можно проходить в любом порядке).
- **Единый обработчик кликов** через делегирование: `data-act` + `data-arg` у кнопок; `data-ui` — справочник и чат; `data-mt` — мобильные вкладки; `data-welcome` — приветствие; `data-lang` — язык. После каждого действия — полная перерисовка `render()` (innerHTML), затем аннотация терминов и синхронизация мобильного режима.
- **Кубик 1 и 2** — отдельные движки (`S`, `A`, `phoneHTML`, `briefHTML`; `T`, `A2`, `phone2`, `brief2`). **Кубики 3–6** — общий движок: `regCube({ key, n, name, nextCube, final, net(face), faces, fresh(), A: {...}, Q: {...}, phone(face) })`, общие действия `GA` (reset, goface, next, closetrap, view, qa), помощники `mk(id)` (отметить шаг), `tp(title, text, restore)` (ловушка), `sn()` (снимок для отката), `barN`, `ar` (строка актива), `okCard`, `badCard`, `doneBtn`.
- **Квест-экзамены кубиков 3–6** (`Q`): последовательность этапов; на каждом — карточка с ситуацией и 2–4 варианта-кнопки (`.choice`). Неверный вариант — ловушка с заголовком квеста и пояснением варианта; верный — переход к следующему этапу, сверху зелёная карточка «Верно» с пояснением. Заголовок appbar: «{Название} · i из N». В конце — баннер «{doneT}» + «{doneText}».
- **Генерация данных**: хэш FNV-1a 32 бит → hex 8 символов: `hsh(s)`; адрес `addrOf(seed) = '0x' + 5 хэшей`; хэш транзакции — 8 хэшей; `short(a)` = первые 6 + «…» + последние 4; числа форматируются через `toLocaleString('ru-RU' | 'en-US')`, до 6 знаков.
- **Учебный QR-код** 21×21 из `<i>`: три «искателя» по углам + биты из хэшей адреса.

## Часть 2. Контент: все 36 граней, экзамены и квесты

### Кубик 1 · Первый кошелёк (сеть: Ethereum)
**Грань 1 · «Старт»** — Блокчейн: общая тетрадь, которую нельзя переписать
- Цель: Попробуйте подделать старую запись в сети и посмотрите, что из этого выйдет. Потом ответьте на три вопроса.
- Шаги (id → текст): `f1-tamper` Изменить запись в блоке 2 (тетрадь на экране телефона); `f1-quiz` Ответить на три вопроса
- «Что здесь происходит»: Каждый блок хранит отпечаток (хэш) предыдущего. Изменили одну запись, и отпечаток блока поменялся, а следующий блок по-прежнему ссылается на старый. Тысячи участников хранят копии тетради и сверяют их, поэтому подделку видно сразу.

**Грань 2 · «Кошелёк»** — Установите кошелёк и защитите его PIN-кодом
- Цель: Найдите в магазине приложений настоящий кошелёк Cube Wallet и создайте новый кошелёк.
- Шаги (id → текст): `f2-app` Установить настоящее приложение; `f2-pin` Создать кошелёк и задать PIN
- «Что здесь происходит»: Мошенники выкладывают копии популярных кошельков и покупают рекламу в поиске. Отличайте их по разработчику, числу установок и ссылке с официального сайта. PIN защищает только этот телефон, а доступ к деньгам даёт seed-фраза.

**Грань 3 · «Seed-фраза»** — 12 слов, которые и есть ваш кошелёк
- Цель: Запишите seed-фразу на бумагу, подтвердите её и выберите, где хранить.
- Шаги (id → текст): `f3-write` Записать фразу офлайн; `f3-confirm` Подтвердить три слова; `f3-store` Выбрать место хранения
- «Что здесь происходит»: Кто знает эти 12 слов, тот владеет деньгами: с любого устройства, без PIN и без вашего ведома. Скриншот, заметки и облако синхронизируются и попадают к злоумышленникам. Бумага или металл в надёжном месте дома — правильный выбор.

**Грань 4 · «Получение»** — Получите первый перевод и добавьте токен
- Цель: Отправьте Маше свой адрес, получите от неё ETH и добавьте токен CUBE по адресу контракта с официального сайта.

### Кубик 4 · Мультичейн и приватность (сеть в статус-баре по граням 1–6: Cube L2, Мост, Мультичейн, Monero, Zcash, Cube L2)

- Цель: У вас 200 USDC в сети Cube L2. Отправьте Маше 50 USDC.
- Шаги (id → текст): `c4-gas` Получить ETH на газ в сети Cube L2; `c4-send` Отправить 50 USDC Маше
- «Что здесь происходит»: В каждой сети комиссию платят её родной монетой. Во второй сети (L2) на Ethereum это ETH, но именно в этой сети. Токены без газа не сдвинуть. L2 собирает много переводов в пакет и публикует его в основной сети, поэтому перевод стоит центы, а не доллары.

- Цель: Перенесите 300 USDC из Ethereum в Cube L2.

- «Что здесь происходит»: Мост блокирует токены в одной сети и выпускает их представление в другой. В контракте моста копятся чужие деньги, и мосты — самая частая цель крупных взломов. Обёрнутый токен стоит столько, сколько надёжен выпустивший его мост. Если у сети есть нативный выпуск, берите его.

- Цель: Научитесь узнавать сеть по адресу и отправьте Петру 0,001 BTC.
- Шаги (id → текст): `c4-formats` Определить сеть для четырёх адресов; `c4-btc` Отправить BTC на адрес Bitcoin
- «Что здесь происходит»: Сети вне семейства Ethereum используют свои форматы адресов: bc1… у Bitcoin, 32–44 символа base58 у Solana, UQ… или EQ… у TON. Адрес 0x на «BTC в сети BNB Chain» отправить можно, но это обёртка в чужой сети, и Bitcoin-кошелёк её не увидит.

**Грань 4 · «Monero»** — Monero: субадреса и доказательство платежа
- Цель: Примите 0,5 XMR от Ани, оплатите худи в магазине Cube Merch и докажите оплату.
- Шаги (id → текст): `c4-xmr-sub` Дать Ане новый субадрес; `c4-xmr-unlock` Дождаться разблокировки (10 блоков); `c4-xmr-proof` Доказать платёж ключом транзакции
- «Что здесь происходит»: В Monero скрыты отправитель, получатель и сумма. Seed-фраза — 25 слов. На каждого отправителя заводят субадрес: так никто не свяжет платежи друг с другом. Полученные монеты 10 блоков нельзя тратить. Чтобы доказать конкретный платёж, отдают ключ транзакции (tx key): он раскрывает только этот перевод.
- Правовая сноска: Приватность — не способ уйти от закона. Ряд бирж исключил Monero из листинга, а в ЕС, по моим данным, с июля 2027 года регулируемым провайдерам запрещено работать с анонимными монетами.

**Грань 5 · «Zcash»** — Zcash: экранированный пул и ключ просмотра
- Цель: Экранируйте 3 ZEC, оплатите счёт дизайнеру с назначением платежа и дайте бухгалтеру Инне доступ на просмотр.
- Шаги (id → текст): `c4-zec-shield` Перевести ZEC в экранированный пул; `c4-zec-memo` Оплатить счёт с memo; `c4-zec-vk` Дать Инне ключ просмотра
- «Что здесь происходит»: У Zcash два вида адресов: прозрачные t1… видны всем, как в Bitcoin, а экранированные скрывают сумму и участников. Единый адрес u1… сам выбирает экранированный пул. Memo — зашифрованное назначение платежа. Ключ просмотра (viewing key) показывает историю, но не даёт тратить: это выборочное раскрытие для бухгалтера или аудитора.
- Правовая сноска: Ключ просмотра позволяет быть приватным для всех и прозрачным для налоговой, бухгалтера или банка по вашему выбору.

**Грань 6 · «Экзамен»** — Экзамен «Зарплата фрилансера»
- Цель: Получите оплату за проект в учебной стране Кубания, перенесите её между сетями и подготовьте отчётность.
- Шаги (id → текст): `c4-exam` Пройти сценарий «Зарплата фрилансера»
- «Что здесь происходит»: Работа с несколькими сетями — это всегда три вопроса: какая сеть, какой токен, чем платить газ. Приватность законна, пока вы можете раскрыть данные тем, кому обязаны: бухгалтеру, банку, налоговой.
- Правовая сноска: В РФ оплата товаров и услуг криптовалютой запрещена (259-ФЗ), поэтому сценарий разыгран в учебной юрисдикции. Доход в криптовалюте декларируется.

Квест-экзамен «Зарплата фрилансера» (шаг `c4-exam`, заголовок ловушки: «Ошибка стоила бы денег»). Финал: **Гонорар получен и учтён** — Оплата в нужной сети, газ есть, перевод в основную сеть надёжным мостом, а бухгалтер видит всё через ключ просмотра.
1. Клиент готов заплатить 500 USDC и спрашивает, куда. Он платит в сети Cube L2.
   - ❌ «Скинуть адрес 0x, он разберётся» → Клиент отправил в BNB Chain, потому что там дешевле. Теперь деньги в сети, которую ваш кошелёк не видит.
   - ✅ «Дать адрес 0x и написать явно: сеть Cube L2, токен USDC» → Адрес, сеть и токен — три вещи, которые надо назвать всегда.
   - ❌ «Дать адрес Monero, так приватнее» → USDC в сети Cube L2 нельзя отправить на адрес Monero.
2. Пришло 500 USDC, но ETH для газа в Cube L2 нет.
   - ✅ «Вывести немного ETH с биржи прямо в сеть Cube L2» → Биржи выводят ETH сразу во вторые сети, без моста.
   - ❌ «Спросить в чате, кто пришлёт газ за USDC» → В личку сразу напишет «помощник», возьмёт USDC и пропадёт.
3. Часть гонорара нужна в основной сети Ethereum.
   - ❌ «Новый мост: 0% комиссии и бонус 20%» → Мосты с бонусами и без истории — любимая цель взломщиков.
   - ✅ «Официальный мост сети или проверенный агрегатор» → Дольше или дороже, но надёжнее.
4. Вы не хотите, чтобы сумма гонорара была видна всем в блокчейне, но всё должно быть законно.
   - ❌ «Прогнать через миксер» → Миксеры попадают под санкции, а деньги после них блокируют биржи и банки.
   - ✅ «Держать в экранированном Zcash и дать бухгалтеру ключ просмотра» → Приватность для всех, прозрачность для тех, кому вы обязаны отчитаться.
5. Конец года. Налоговая отчётность.
   - ✅ «Выгрузить историю операций и передать бухгалтеру ключи просмотра» → Доход в криптовалюте декларируется так же, как любой другой.
   - ❌ «Не декларировать: блокчейн анонимный» → Блокчейн публичен, а биржи передают данные налоговым органам. Неуплата налога — нарушение закона.

Финал кубика 4: Вы платите газ во второй сети, выбираете надёжный мост и нативный токен, различаете форматы адресов, принимаете Monero на субадрес, экранируете Zcash и даёте бухгалтеру только ключ просмотра. Кнопка «Дальше: Кубик 5 «DeFi»».

### Кубик 5 · DeFi (сеть в статус-баре по граням 1–6: CubeChain, Ethereum, CubeLend, CubeSwap, Ethereum, Машина времени)
**Грань 1 · «Стейкинг»** — Стейкинг и выбор валидатора
- Цель: Застейкайте 1 000 CUBE в сети CubeChain и получите первую награду.
- Шаги (id → текст): `c5-stake` Выбрать надёжного валидатора; `c5-reward` Получить награду за эпоху
- «Что здесь происходит»: В сетях с доказательством доли валидаторы подтверждают блоки под залог. За ошибки и мошенничество сеть сжигает часть залога (слэшинг), и делегаторы теряют вместе с валидатором. Нулевая комиссия не компенсирует плохую историю.

**Грань 2 · «Ликвидный стейкинг»** — Ликвидный стейкинг и дисконт
- Цель: Внесите 1 ETH в протокол ликвидного стейкинга, а через неделю верните ETH без потерь.
- Шаги (id → текст): `c5-lst` Получить lsETH за 1 ETH; `c5-queue` Вывести через очередь, а не продавать с дисконтом
- «Что здесь происходит»: Ликвидный стейкинг выдаёт токен-расписку (lsETH), который можно передавать и продавать. Его цена на рынке может уходить ниже ETH, особенно в панику. Протокол погашает его 1:1 через очередь вывода, но это занимает дни.

**Грань 3 · «Кредитование»** — Заём под залог и health factor
- Цель: Займите USDC под 2 ETH так, чтобы пережить падение ETH на 30%.
- Шаги (id → текст): `c5-borrow` Занять с health factor выше 1,5; `c5-crash` Пережить падение ETH на 30% без ликвидации
- «Что здесь происходит»: Health factor = залог × порог ликвидации ÷ долг. Здесь порог 80%. Когда HF опускается ниже 1, любой может погасить часть вашего долга и забрать залог со скидкой. Запас по HF — ваша подушка на случай падения цены.

**Грань 4 · «Пулы и фарминг»** — Пул ликвидности и непостоянные потери
- Цель: Внесите ETH и USDC в пул, разберитесь с непостоянными потерями и выберите фарм.
- Шаги (id → текст): `c5-il` Посчитать непостоянные потери; `c5-farm` Выбрать проверенный фарм
- «Что здесь происходит»: Пул держит две монеты в пропорции по стоимости. Когда цена одной растёт, пул продаёт её по пути, и вы получаете меньше, чем если бы просто держали. При росте в 2 раза это около 5,7%. Комиссии могут это перекрыть, а 3 000% годовых у анонимов обычно означают, что деньги заберут.

**Грань 5 · «Стейблкоины»** — Чем обеспечены стейблкоины
- Цель: Разберитесь, что стоит за тремя стейблкоинами, и разместите 1 000 $.
- Шаги (id → текст): `c5-types` Определить тип обеспечения; `c5-stable` Разместить без алгоритмического стейблкоина
- «Что здесь происходит»: Фиатный стейблкоин держится на резервах в банке и доверии к эмитенту. Криптозалоговый — на избыточном залоге в смарт-контракте. Алгоритмический без залога держится только на вере рынка, и при панике цена уходит к нулю. Высокая доходность — плата за этот риск.

**Грань 6 · «Экзамен»** — Экзамен «Шторм»
- Цель: Проведите портфель через месяц штормового рынка. Машина времени отмотает неделю, если вы ошибётесь.
- Шаги (id → текст): `c5-storm` Пережить шторм без потерь
- «Что здесь происходит»: Шторм проверяет всё сразу: запас по заёму, терпение с ликвидным стейкингом, умение пройти мимо обещаний сверхдоходности и привычку проверять первоисточник.
- Правовая сноска: Это учебная модель, а не инвестиционная рекомендация.

Квест-экзамен «Шторм» (шаг `c5-storm`, заголовок ловушки: «Машина времени: отматываем неделю»). Финал: **Портфель пережил шторм** — Ни одной ликвидации, ни одной продажи в панику, ни одного рагпула.
1. Неделя 1. ETH упал на 25%. HF вашего займа опустился с 1,9 до 1,4.
   - ✅ «Довнести залог или погасить часть долга» → HF снова выше 1,8, следующее падение вас не ликвидирует.
   - ❌ «Занять ещё и докупить ETH на просадке» → HF упал до 1,05. Ещё −5%, и залог ушёл ликвидатору.
2. Неделя 2. lsETH на DEX стоит 0,93 ETH. Деньги вам не нужны ближайший месяц.
   - ❌ «Продать всё на DEX, пока не стало хуже» → Вы зафиксировали минус 7%, хотя протокол погасил бы lsETH 1:1.
   - ✅ «Не продавать в панику; если нужен ETH, выйти через очередь вывода» → Дисконт на рынке — не потеря, пока вы не продали.
3. Неделя 3. В чате: «Новый фарм, 5 000% годовых, закрываем через 2 часа!»
   - ❌ «Зайти на 10% портфеля, вдруг повезёт» → Через сутки фарм закрылся вместе с депозитами.
   - ✅ «Пройти мимо: команда анонимная, контракт не проверен» → Срочность и нереальная доходность — два признака ловушки.
4. Неделя 4. USDCube на сутки подешевел до 0,88 $ из-за проблем банка, где хранится часть резервов.
   - ✅ «Проверить отчёт о резервах и заявление эмитента, а не слухи» → Резервы оказались целы, через три дня цена вернулась к 1 $.
   - ❌ «Срочно переложить всё в TerraCube, он «держится»» → Через неделю TerraCube потерял привязку окончательно.

Финал кубика 5: Вы выбираете валидатора по истории, а не по нулевой комиссии, не продаёте ликвидный стейкинг в панике, держите запас по health factor, считаете непостоянные потери и отличаете обеспеченный стейблкоин от алгоритмического. Кнопка «Дальше: Кубик 6 «Смарт-контракты и финал»».

### Кубик 6 · Смарт-контракты и финал (сеть в статус-баре по граням 1–6: Ethereum, Ethereum, Ethereum, Ethereum, Ethereum, Sepolia (тест))
**Грань 1 · «Чтение кода»** — Читаем контракт перед покупкой
- Цель: Друг советует купить новый токен CMOON. Найдите в коде строки, которые дают владельцу власть над вашими деньгами.
- Шаги (id → текст): `c6-mint` Найти скрытую эмиссию; `c6-fee` Найти комиссию без верхнего предела
- «Что здесь происходит»: onlyOwner значит, что функцию может вызвать только владелец контракта. «Награда держателям», которая выпускает токены владельцу, — это печатный станок: он напечатает и продаст. Комиссия без верхнего предела может стать 100%, и продать токен станет невозможно.

**Грань 2 · «Подпись вызова»** — Что на самом деле подписывает кошелёк
- Цель: Два сайта просят подтвердить транзакцию. Прочитайте расшифровку вызова, а не кнопку сайта.
- Шаги (id → текст): `c6-decode` Подтвердить честный перевод, сверив расшифровку; `c6-reject` Отклонить setApprovalForAll под видом минта
- «Что здесь происходит»: Транзакция к контракту — это функция и её аргументы (calldata). Первые 4 байта — селектор функции: a9059cbb это transfer, a22cb465 это setApprovalForAll. Хороший кошелёк расшифровывает их. setApprovalForAll отдаёт оператору право забрать все NFT коллекции.

**Грань 3 · «Отзыв разрешений»** — Отзываем старые разрешения
- Цель: Проверьте, кому вы разрешили тратить токены, и отзовите всё лишнее.
- Шаги (id → текст): `c6-revoke` Отозвать три опасных разрешения
- «Что здесь происходит»: Разрешения (approve и setApprovalForAll) живут бессрочно, даже если вы забыли о сайте. Раз в несколько месяцев проверяйте их в кошельке или обозревателе блоков и отзывайте лишние. Отзыв — это обычная транзакция, подписи на сторонних сайтах для него не нужны.

**Грань 4 · «Мультиподпись»** — Казна клуба на мультиподписи 2 из 3
- Цель: Оплатите из казны клуба 500 USDC дизайнеру. Владельцы: вы, Маша и Пётр, нужно 2 подписи из 3.
- Шаги (id → текст): `c6-propose` Предложить транзакцию и подписать; `c6-exec` Собрать вторую подпись и исполнить
- «Что здесь происходит»: Мультиподпись требует несколько ключей для каждой операции, поэтому кража одного ключа ничего не даёт. Самая опасная операция в ней — смена владельцев и порога. Такие просьбы проверяют по другому каналу связи.

**Грань 5 · «Свой токен»** — Выпускаем свой ERC-20
- Цель: Выпустите учебный токен в тестовой сети и откажитесь от прав владельца.
- Шаги (id → текст): `c6-deploy` Развернуть контракт из своего кошелька; `c6-renounce` Отказаться от прав владельца
- «Что здесь происходит»: Выпустить токен может любой за пару минут, поэтому сам факт токена ничего не значит. Отказ от прав владельца (renounceOwnership) показывает, что больше никто не напечатает токены и не поменяет правила. Деплой подписывают в своём кошельке, приватный ключ никому не отдают.
- Правовая сноска: Публичное размещение токенов и привлечение денег регулируется законом. Здесь токен учебный и живёт только в тестовой сети.

**Грань 6 · «Финал»** — Финал в тестовой сети и сертификат
- Цель: Пройдите финальный чек-лист в тестовой сети Sepolia и выпустите непередаваемый сертификат.
- Шаги (id → текст): `c6-sepolia` Пройти финальный чек-лист; `c6-cert` Выпустить сертификат Cryptocube
- «Что здесь происходит»: Тестовые сети работают как настоящие, но их монеты ничего не стоят и раздаются бесплатно в кранах. Soulbound-токен нельзя передать или продать: он подтверждает, что именно этот адрес прошёл курс.
- Правовая сноска: В прототипе выпуск сертификата смоделирован. В рабочей версии он пройдёт в настоящей сети Sepolia.

Квест-экзамен «Финал в Sepolia» (шаг `c6-sepolia`, заголовок ловушки: «Стоп, это ошибка»). Финал: **Чек-лист пройден** — Осталось выпустить сертификат.
1. Для финала нужен тестовый ETH в сети Sepolia.
   - ❌ «Купить 1 SepoliaETH за 15 $ у продавца в чате» → Тестовые монеты ничего не стоят и раздаются бесплатно. Продавец просто заберёт 15 $.
   - ✅ «Взять бесплатно в кране (faucet)» → Кран бесплатно выдаёт тестовые монеты.
2. Где вы храните seed-фразу основного кошелька?
   - ✅ «Офлайн: на бумаге или металле, в надёжном месте» → Seed-фраза не должна касаться интернета.
   - ❌ «В заметках телефона, они синхронизируются» → Облачная синхронизация — это копия ключей на чужом сервере.
3. Крупная сумма лежит…
   - ✅ «На аппаратном кошельке, на горячем только мелочь» → Ключи от крупных сумм не должны быть на устройстве, которое ходит в интернет.
   - ❌ «На бирже, там же есть поддержка» → Не ваши ключи — не ваши монеты. Вспомните CubeX.
4. Кошелёк показывает: mint(to: ваш адрес), контракт Cryptocube Certificate, сеть Sepolia, газ 0,0003 SepoliaETH.
   - ❌ «Переключиться на основную сеть Ethereum, чтобы сертификат был «настоящим»» → Контракт сертификата живёт в Sepolia. В основной сети вы заплатили бы настоящий газ за вызов по чужому адресу.
   - ✅ «Подписать: сеть тестовая, функция и адрес понятны» → Вы проверили сеть, функцию и получателя. Это и есть привычка, ради которой был курс.

Финал кубика 6: Курс Cryptocube пройден. Вы читаете контракты, расшифровываете вызовы, отзываете разрешения, работаете с мультиподписью, выпускаете свой токен и получили сертификат в тестовой сети. Показывается сертификат (см. ниже).

## Часть 3. Ловушки, словарь, библиотека, приветствие

### Ловушки (заголовок — текст разбора)
Ловушки с откатом (кнопка «Отмотать время и повторить») — те, где в тексте есть «Отмотаем время»; остальные закрываются кнопкой «Понятно, попробую иначе».
- **Это поддельное приложение** — Разработчик «Cube Wallett Inc» (две t), 1 тыс. установок и пометка «Реклама». Такие копии крадут seed-фразу при первом же вводе. Ставьте кошелёк только по ссылке с официального сайта.
- **Друга взломали** — Аккаунт Маши угнали, и писал мошенник. Получив 12 слов, он вывел бы всё за минуту. Seed-фразу не просит никто: ни друзья, ни поддержка, ни «проверка настроек».
- **Это токен-подделка** — Название и тикер совпадают, а адрес контракта — нет (в конце «l9» вместо «19»). Такой токен ничего не стоит, а сайт, где его «покупают», крадёт деньги.
- **Комиссия дороже половины перевода** (с откатом) — Вы отдали {комиссия} ETH валидаторам за перевод {сумма} ETH. Перевод другу не горит: «Обычно» дошло бы за полминуты за 0,0042 ETH. Отмотаем время, попробуйте ещё раз.
- **Это мошенник** — Настоящая поддержка не пишет первой и никогда не просит seed-фразу. Аккаунт @CubeWallet_Help_24 создан вчера. Пожалуйтесь на него и не отвечайте.
- **Вы ввели seed-фразу на поддельном сайте** — Через минуту кошелёк опустел бы: фраза ушла на сервер мошенников. Ни один настоящий сервис не просит seed-фразу для «разблокировки» или «проверки».
- **Деньги ушли мошеннику** — Адрес из последнего «перевода» совпадал с Машиным только по краям: 0x9A4e…1b20. Середина другая. Отмотаем время: сверьте адрес целиком или возьмите из контактов.
- **«Инструмент восстановления» — дрейнер** — Сайт wallet-repair.example попросил бы подписать разрешение на все токены. Настоящая поддержка не пишет первой и никуда не просит подключаться.
- **Дрейнер забрал все USDC** (с откатом) — Подпись Permit разрешила адресу 0xD4a1E57b… тратить ваши USDC без ограничений и бессрочно. Он сразу вывел 200 USDC. Отмотаем время: прочитайте предпросмотр и отклоните.
- **Seed-фраза уже в коробке** — Продавец сгенерировал фразу заранее и оставил себе копию. Всё, что вы переведёте на это устройство, он заберёт. Настоящее устройство всегда создаёт новую фразу при настройке.
- **Вирус подменил адрес на компьютере** — В приложении адрес отличался от того, что на экране устройства. Подтвердив его, вы отправили бы средства мошеннику. Верьте только экрану устройства.
- **Паспорт ушёл мошеннику** — «Менеджер» из мессенджера соберёт на ваше имя кредиты и аккаунты для отмывания денег. Биржа принимает документы только в своём приложении и никогда не пишет первой.
- **SIM-swap: номер перевыпустили** — Мошенник с поддельной доверенностью перевыпустил вашу SIM-карту и получил все SMS-коды. SMS лучше, чем ничего, но коды из приложения-аутентификатора не проходят через оператора.
- **Тонкий стакан: средняя цена 3 166** — Рыночный ордер забрал заявки подряд: 0,05 по 3 001, 0,05 по 3 012, 0,1 по 3 090 и 0,1 по 3 400. Вы переплатили почти 5,5%. В тонком стакане покупайте лимитным ордером. Отмотаем время.
- **Стоп выше рынка сработал сразу** — Стоп-лосс на продажу ставят ниже текущей цены. Ордер по 3 050 при цене 3 000 исполнился мгновенно, и только что купленный ETH продан.
- **USDT ушли в BNB Chain** — Адрес 0x подходит к обеим сетям, поэтому биржа отправила. Но ваш кошелёк смотрит в Ethereum и денег не видит. Вернуть можно, только добавив сеть BNB Chain и купив BNB на комиссию, а в чужом кошельке — никак. Отмотаем время.
- **Депозит без memo потерялся** — Биржа принимает TON всех клиентов на один адрес и узнаёт ваш перевод по memo. Без него — заявка в поддержку и недели ожидания, а иногда и потеря. Отмотаем время.
- **Купили токен-ловушку** — Этот CUBE создан два часа назад, в пуле всего 310 $. Контракт разрешает покупку, но запрещает продажу (honeypot). Настоящий адрес контракта — на официальном сайте проекта и в списке токенов. Отмотаем время.
- **Бессрочное разрешение сработало против вас** — Через месяц в роутере нашли уязвимость. Все, кто разрешил тратить USDC без ограничений, потеряли весь баланс, а не 100. Отмотаем время: разрешите ровно сумму обмена.
- **Сэндвич-атака** — Бот увидел заявку в мемпуле, купил ETH прямо перед вами и продал сразу после. С допуском …% вы получили … USDC вместо 1 500. Отмотаем время.
- **Бот взял 20 USDC и пропал** — «Помощник с газом» из чата просит прислать USDC вперёд. Газ так никто и не прислал. Газ берут с биржи (вывод прямо в нужную сеть) или через мост.
- **Мост взломали** — Через сутки MegaBridge взломали, его mbUSDC подешевел до 0,18 $. Новый мост с бонусами — самый рискованный вариант: в нём копятся чужие деньги, а код не проверен временем. Отмотаем время.
- **Обёртка потеряла привязку** — bUSDC — расписка моста. Когда у моста проблемы, она торгуется с дисконтом, и выйти по 1 $ уже нельзя. Если у сети есть нативный USDC, берите его.
- **Пётр получил BTCB в чужой сети** — Биржа отправила обёрнутый BTC в BNB Chain на адрес 0x. Bitcoin-кошелёк Петра его не видит, а ключей от этого адреса в другой сети у него может и не быть. Отмотаем время.
- **Один адрес для всех** — Основной адрес работает, но если раздавать его всем, отправители смогут понять, что платят одному человеку. На каждого отправителя заводят отдельный субадрес.
- **Магазин получил ключ траты** — Секретный ключ траты даёт полный контроль над кошельком. «Магазин» или любой, кто увидит переписку, заберёт все XMR.
- **Seed-фраза ушла в чат поддержки** — 25 слов — это весь кошелёк. Для доказательства платежа они не нужны.
- **Платёж без назначения** — Олег получает оплату от десятка клиентов. Без memo «Счёт №12» он не поймёт, кто заплатил, а у вас не будет записи для бухгалтерии. Memo в Zcash зашифрован и виден только получателю.
- **Слэшинг** — MaxYield подписал два разных блока на одной высоте. Сеть сожгла 5% всех ставок у этого валидатора, включая ваши 50 CUBE. Нулевая комиссия не стоила потерь. Отмотаем время.
- **Продали с дисконтом 8%** — В панику lsETH на DEX стоил 0,92 ETH. Через очередь протокол вернул бы 1 ETH за 5 дней, а деньги были нужны только через неделю. Отмотаем время.
- **Ликвидация** — HF упал до …. Ликвидатор погасил часть долга и забрал ваш ETH со скидкой 5%. Отмотаем время к моменту до займа.
- **Депег: TerraCube стоит 0,04 $** — Крупный держатель продал, цена ушла ниже 1 $, механизм сжигания напечатал горы LUNAcube, и за два дня оба токена обесценились. 20% годовых были платой за этот риск. Отмотаем время.
- **Владелец напечатал и продал** — Через неделю владелец вызвал rewardHolders, выпустил 50 млн CMOON и продал их в пул. Цена упала на 98%. Потом поставил комиссию 100%, и продать остатки стало невозможно.
- **Все NFT ушли оператору** — Кнопка обещала бесплатный минт, а расшифровка показывала setApprovalForAll(оператор, true). Оператор забрал все 4 NFT коллекции CubeApes одной транзакцией.
- **«Бесплатный отзыв» оказался дрейнером** — Сайт revoke-free.example попросил подписать Permit «для проверки». Отзыв разрешений — обычная транзакция в вашем кошельке, никаких подписей на сторонних сайтах.
- **Казну увели** — «Пётр с нового номера» был мошенником. Порог 1 из 3 и новый владелец позволили ему одной подписью вывести все 5 000 USDC.
- **Ключ ушёл «сервису»** — easy-token.example попросил приватный ключ, «чтобы развернуть за вас». Через минуту с этого адреса ушли все средства во всех сетях. Деплой подписывают в своём кошельке.
- **Rug pull** (с откатом) — Через три дня анонимная команда MoonFarm вывела все деньги из контракта через скрытую функцию. 3 000% годовых платились из депозитов новых участников. Отмотаем время.
- **Инна получила seed-фразу / Инна получила ключ траты** — Бухгалтеру нужно видеть операции, а не распоряжаться деньгами. С этим ключом Инна, или любой, кто взломает её почту, может потратить все ZEC. Для отчётности есть ключ просмотра.

### Словарь: 55 терминов (порядок сохранить)
- Кошелёк (кубик 1) — Приложение или устройство, которое хранит ключи и подписывает транзакции. Сами монеты лежат в блокчейне, а не в кошельке.
- Seed-фраза (кубик 1) — 12–24 слова, из которых получаются все ключи кошелька. Кто знает фразу, тот владеет деньгами. Хранится только офлайн.
- Приватный ключ (кубик 1) — Секретное число, которым подписываются транзакции. Получается из seed-фразы. Никому не передаётся.
- Адрес (кубик 1) — Публичный идентификатор для получения средств, как номер счёта. Его можно давать всем.
- Транзакция (кубик 1) — Подписанная команда сети: перевести монеты или вызвать функцию контракта. После включения в блок её нельзя отменить.
- Блок (кубик 1) — Пачка транзакций, которую сеть записывает в цепочку. Каждый блок ссылается на предыдущий, поэтому прошлое нельзя переписать незаметно.
- Блокчейн (кубик 1) — Общая публичная база данных из цепочки блоков, которую одновременно хранят тысячи компьютеров.
- Газ (кубик 1) — Плата сети за обработку транзакции. Платится родной монетой сети, например ETH в Ethereum.
- Комиссия (кубик 1) — Сколько вы платите за операцию: сети (газ), бирже или протоколу.
- Мемпул (кубик 1) — Очередь транзакций, которые ещё не попали в блок. Её видят все, включая ботов.
- Подтверждение (кубик 1) — Новый блок поверх блока с вашей транзакцией. Чем больше подтверждений, тем надёжнее перевод.
- Обозреватель блоков (кубик 1) — Сайт для просмотра транзакций и адресов, например Etherscan. Показывает, что реально произошло в сети.
- Токен (кубик 1) — Актив, выпущенный смарт-контрактом поверх сети. Подлинность определяет адрес контракта, а не название.
- Фишинг (кубик 2) — Поддельный сайт или письмо, которые выманивают seed-фразу, пароль или подпись.
- Подмена адреса (кубик 2) — Мошенник создаёт адрес, похожий на нужный по краям, и подбрасывает его в историю переводов (address poisoning).
- Дрейнер (кубик 2) — Вредоносный контракт или сайт, который после вашей подписи выводит все токены.
- Permit (кубик 2) — Подпись-разрешение тратить ваши токены без отдельной транзакции. Опасна тем, что выглядит как обычная подпись.
- Аппаратный кошелёк (кубик 2) — Отдельное устройство, которое хранит ключи офлайн и показывает транзакцию на своём экране.
- KYC (кубик 3) — Know Your Customer: проверка личности клиента, которую по закону проводят биржи.
- 2FA (кубик 3) — Двухфакторная защита: кроме пароля нужен код из приложения или ключа.
- Биржа (CEX) (кубик 3) — Централизованная площадка: хранит ваши средства у себя и сводит покупателей с продавцами.
- DEX (кубик 3) — Децентрализованная биржа: обмен идёт через смарт-контракт прямо из вашего кошелька.
- Стакан (кубик 3) — Список заявок на покупку и продажу по разным ценам.
- Лимитный ордер (кубик 3) — Заявка, которая исполнится только по вашей цене или лучше.
- Стоп-лосс (кубик 3) — Заявка, которая автоматически продаёт актив, если цена падает до заданного уровня.
- Memo (кубик 3) — Метка платежа (тег). Биржи по ней узнают, чей депозит пришёл на общий адрес.
- Approve (кубик 3) — Разрешение контракту тратить ваш токен. Бывает на сумму или без ограничений.
- Проскальзывание (кубик 3) — Разница между ожидаемой и фактической ценой обмена. Допуск задаёт, на сколько хуже вы готовы получить.
- MEV (кубик 3) — Прибыль, которую извлекают из порядка транзакций в блоке. Пример — сэндвич-атака.
- Сэндвич-атака (кубик 3) — Бот покупает перед вашим обменом и продаёт сразу после, забирая разницу в пределах вашего допуска.
- L2 (кубик 4) — Вторая сеть поверх основной: собирает транзакции в пакеты и публикует их в L1. Дешевле и быстрее.
- Мост (кубик 4) — Протокол, который блокирует токены в одной сети и выпускает их представление в другой.
- Обёрнутый токен (кубик 4) — Расписка на актив из другой сети. Стоит столько, сколько надёжен её эмитент или мост.
- Monero (кубик 4) — Сеть с приватностью по умолчанию: скрыты отправитель, получатель и сумма.
- Субадрес (кубик 4) — Дополнительный адрес Monero того же кошелька. Платежи на разные субадреса нельзя связать.
- Zcash (кубик 4) — Сеть с выбором: прозрачные адреса как у Bitcoin или экранированный пул со скрытыми данными.
- Ключ просмотра (кубик 4) — Ключ, который показывает историю кошелька, но не позволяет тратить. Для бухгалтера и аудитора.
- Стейкинг (кубик 5) — Залог монет за валидатора в сети с доказательством доли. Приносит награду, но есть риск штрафа.
- Валидатор (кубик 5) — Участник сети, который подтверждает блоки под залог.
- Слэшинг (кубик 5) — Штраф сети за нарушения валидатора: сжигается часть залога, включая делегированный.
- Health factor (кубик 5) — Запас прочности займа: залог × порог ликвидации ÷ долг. Ниже 1 — ликвидация.
- Ликвидация (кубик 5) — Принудительное погашение долга за счёт залога, когда его стоимость падает.
- Пул ликвидности (кубик 5) — Контракт с запасом двух токенов, через который проходят обмены. Поставщики получают комиссии.
- Непостоянные потери (кубик 5) — Недополученная прибыль поставщика ликвидности по сравнению с простым хранением, когда цены расходятся.
- Фарминг (кубик 5) — Размещение токенов в протоколе ради наград. Сверхвысокая доходность почти всегда означает сверхвысокий риск.
- Стейблкоин (кубик 5) — Токен, привязанный к валюте, обычно к доллару. Надёжность зависит от обеспечения.
- Депег (кубик 5) — Потеря стейблкоином привязки к своей валюте.
- Смарт-контракт (кубик 6) — Программа в блокчейне. Её код публичен, и после деплоя она выполняется без посредников.
- Calldata (кубик 6) — Данные вызова контракта: селектор функции (первые 4 байта) и аргументы.
- setApprovalForAll (кубик 6) — Разрешение оператору распоряжаться всеми NFT коллекции.
- Мультиподпись (кубик 6) — Кошелёк, которому для операции нужно несколько подписей из заданного числа владельцев, например 2 из 3.
- ERC-20 (кубик 6) — Стандарт взаимозаменяемых токенов в Ethereum.
- onlyOwner (кубик 6) — Модификатор: функцию может вызвать только владелец контракта.
- Тестнет (кубик 6) — Тестовая сеть, монеты которой ничего не стоят. Sepolia — тестнет Ethereum.
- Soulbound-токен (кубик 6) — Непередаваемый токен: его нельзя продать или отправить, он привязан к адресу.

// Ключи API хранятся только в переменных окружения Vercel и не попадают в браузер.
// Провайдеры пробуются по очереди: Groq → OpenRouter → любой OpenAI-совместимый (AI_*).
// Если первый не ответил или упёрся в лимит, вопрос уходит следующему.
//   GROQ_API_KEY        — ключ Groq (console.groq.com)
//   GROQ_MODEL          — необязательно; без него модель выбирается из списка доступных у Groq
//   OPENROUTER_API_KEY  — ключ OpenRouter (openrouter.ai)

const LIMIT = 20, WINDOW_MS = 10 * 60 * 1000; // не больше 20 вопросов за 10 минут с одного IP
const hits = new Map();
const clip = (v, n) => String(v || '').slice(0, n);

function providers() {

// Подбор модели из списка провайдера: кэшируется на время жизни функции.
const picked = {};
async function pickModel(p, exclude) {
  if (picked[p.name] && picked[p.name] !== exclude) return picked[p.name];
  try {
    const r = await fetch(p.base + '/models', { headers: { Authorization: 'Bearer ' + p.key } });
    const j = await r.json();
    let ids = (j.data || []).map(m => m.id).filter(id => id !== exclude && !p.skip.test(id));
    if (p.free) ids = ids.filter(id => id.endsWith(':free'));
    for (const re of p.prefer) { const hit = ids.find(id => re.test(id)); if (hit) return (picked[p.name] = hit); }
    return (picked[p.name] = ids[0] || null);
  } catch (e) { return null; }
}

async function callProvider(p, messages) {
  let model = p.model || picked[p.name] || await pickModel(p);
  if (!model) return { status: 502 };
  let r = await callModel(p, model, messages);
  if (r.status === 404 || r.status === 400) {
    const alt = await pickModel(p, model);
    if (alt && alt !== model) { console.error('AI model replaced', p.name, model, '->', alt); r = await callModel(p, alt, messages); }
  }
  return r;
}

async function callModel(p, model, messages) {
  const ctl = new AbortController();
  const timer = setTimeout(() => ctl.abort(), 15000);
  try {
    const r = await fetch(p.base + '/chat/completions', {
      method: 'POST', signal: ctl.signal,
      headers: Object.assign({ 'Content-Type': 'application/json', Authorization: 'Bearer ' + p.key }, p.headers || {}),
      body: JSON.stringify({ model, temperature: 0.3, max_tokens: 500, messages }),
    });
    const j = await r.json().catch(() => ({}));
    const answer = r.ok && j.choices && j.choices[0] && j.choices[0].message && j.choices[0].message.content;
    if (answer) return { answer: String(answer).trim() };
    console.error('AI provider error', p.name, model, r.status, JSON.stringify(j).slice(0, 300));
    return { status: r.status };
  } catch (e) {
    console.error('AI provider timeout', p.name);
    return { status: 504 };
  } finally { clearTimeout(timer); }
}

module.exports = async (req, res) => {
  if (req.method !== 'POST') { res.setHeader('Allow', 'POST'); return res.status(405).json({ error: 'method_not_allowed' }); }
  const list = providers();
  if (!list.length) return res.status(501).json({ error: 'not_configured' });

  const ip = String(req.headers['x-forwarded-for'] || '').split(',')[0].trim() || 'unknown';
  const now = Date.now();
  const recent = (hits.get(ip) || []).filter(t => now - t < WINDOW_MS);
  if (recent.length >= LIMIT) return res.status(429).json({ error: 'rate_limited' });
  recent.push(now); hits.set(ip, recent);

  let body = req.body;
  if (typeof body === 'string') { try { body = JSON.parse(body); } catch (e) { body = {}; } }
  const msgs = Array.isArray(body && body.messages) ? body.messages.slice(-8) : [];
  const clean = msgs
    .filter(m => m && (m.role === 'user' || m.role === 'assistant') && typeof m.content === 'string')
    .map(m => ({ role: m.role, content: clip(m.content, 1200) }));
  if (!clean.length || clean[clean.length - 1].role !== 'user') return res.status(400).json({ error: 'bad_request' });

  const messages = [{ role: 'system', content: systemPrompt(body.context) }, ...clean];
  let last = 502;
  for (const p of list) {
    const r = await callProvider(p, messages);
    if (r.answer) return res.status(200).json({ answer: r.answer, provider: p.name });
    last = r.status;
  }
  return res.status(last === 429 ? 429 : 502).json({ error: 'provider_error' });
};
